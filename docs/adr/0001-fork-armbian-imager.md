# ADR 0001. Форк Armbian Imager как основа

Статус: принято.

## Контекст

Плата Wukong Pi Zero настраивалась только руками: образ из `wukong-build` записывался на карту, затем через UART задавались пользователь и сеть. Нужна настольная программа для Windows и Linux в духе Raspberry Pi Imager: задать настройки на компьютере, прошить карту, включить плату и сразу зайти по SSH.

Armbian Imager 2.0.0 был проверен на образе `Armbian_23.02.2_Wukongpi_bullseye_current_5.15.93.img`:

| Что | Вывод |
|---|---|
| Запись, проверка, защита дисков, GUI, русский язык | годятся как есть |
| `PRESET_*` в `/root/.not_logged_in_yet` | на Armbian 23.02 не работает: `armbian-firstlogin` не читает этот файл как настройки |
| `armbian-ext4fs` на классическом ext4 образа | не подходит: паника при `s_desc_size=0`, порча соседнего дескриптора, режим файлов 0777 |
| Каталог, обновления, отправка логов | привязаны к инфраструктуре Armbian |

Писать программу с нуля значит заново делать самое рискованное: выбор диска, запись и проверку.

## Решение

Форк `armbian/imager` (`Kostec/imager`, ветка `wukong`, GPL-2.0-or-later; лицензия, копирайты и упоминание оригинала сохраняются). Берём запись, проверку, защиту дисков и интерфейс. Заменяем механизм настроек, каталог и брендинг, отключаем обновления, отправку логов и все обращения к серверам Armbian. Новое лежит в новых файлах, правки upstream точечные. Код других плат, QDL и macOS не удаляется.

## Последствия

- Обновления upstream можно забирать, но при каждом слиянии нужно проверять, что не вернулись обращения к `armbian.com`.
- Лицензия форка наследуется: GPL для программы; новый crate `classic-ext4` под MIT, как `armbian-write-conf`.
- В репозитории остаётся неиспользуемый код QDL и macOS: он не проверяется и в интерфейсе для Wukong не появляется.
- Подпись установщика и автообновление не предусмотрены, поэтому Windows показывает предупреждение SmartScreen.
