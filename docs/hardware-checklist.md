# Чек-лист проверки на плате Wukong Pi Zero

Проверка реальной записи и реальной платы, то есть того, что нельзя проверить автоматически: карта, Wi-Fi, Ethernet, mDNS и оверлеи. Времени нужно около часа. Шаги идут по порядку, отмечайте выполненные.

Что понадобится:

- компьютер с Windows и картридером;
- SD-карта от 4 ГБ, все данные на ней будут стёрты;
- плата, питание, кабель Ethernet и роутер с DHCP;
- сеть Wi-Fi WPA2, для которой вы знаете пароль;
- адаптер USB-UART на 3,3 В для консоли, желательно, он нужен при сбоях;
- образ `Armbian_23.02.2_Wukongpi_bullseye_current_5.15.93.img`;
- открытый SSH-ключ на компьютере. Если его нет: `ssh-keygen -t ed25519`.

## 1. Установщик

Готовых релизов нет, установщик собирается из ветки `wukong`:

```powershell
cd D:\Projects\Wukong\wukong-imager
npm ci
npm run tauri:build
```

Установщик появится здесь: `src-tauri\target\release\bundle\nsis\Wukong Imager_2.0.0_x64-setup.exe`. Берите только что собранный файл: лежащий там раньше мог быть собран до появления экрана настроек.

- [ ] Установщик запускается. Он не подписан, поэтому SmartScreen может показать предупреждение: «Подробнее» → «Выполнить в любом случае».

## 2. Запуск и настройки

- [ ] Программа просит права администратора. Без них она не увидит карту.
- [ ] Открывается сразу с Wukong Pi Zero, без выбора производителя и платы.
- [ ] Кнопка «Выбрать файл образа» принимает образ. Настройки доступны, предупреждения об образе нет.

Заполните профиль. Значения ниже можно заменить на свои, но дальше по тексту используются они:

| Поле | Значение |
|---|---|
| Имя устройства | `wukong` |
| Пользователь и пароль | `tester` и ваш пароль |
| Wi-Fi | имя сети, пароль, страна |
| Часовой пояс, локаль, раскладка | например, `Europe/Moscow`, `ru_RU.UTF-8`, `ru` |
| SSH | включён, вход по паролю включён, вход root выключен |
| Открытые ключи | содержимое вашего `id_ed25519.pub`, затем «Импорт» |
| Интерфейсы | `i2c0`, `spi-spidev` |
| Скрипт первой загрузки | см. ниже |

Скрипт для проверки:

```bash
#!/bin/bash
echo "свой скрипт отработал"
touch /var/tmp/my-script-done
```

- [ ] Профиль сохранился и остался на месте после перезапуска программы.

## 3. Запись карты

- [ ] Карта видна в списке, системные диски скрыты.
- [ ] На экране подтверждения указаны имя и размер карты, сводка настроек и предупреждение о стирании данных.
- [ ] Запись и проверка завершились без ошибки.
- [ ] Windows может предложить отформатировать карту после записи. Откажитесь: раздел ext4 для неё нечитаем, это нормально.

## 4. Настройки на компьютере

Откройте `%APPDATA%\io.github.kostec.wukongimager\settings.json` и найдите в нём пароль пользователя и пароль Wi-Fi, которые вы вводили.

- [ ] Обоих паролей в файле нет. Рядом с ними хранятся только хеш `$6$…` и 64 шестнадцатеричных символа ключа Wi-Fi.

## 5. Первая загрузка

Вставьте карту, подключите Ethernet, по возможности UART (115200 8N1), затем питание. Первая загрузка идёт несколько минут: растёт раздел, создаются ключи хоста, собирается локаль.

- [ ] В консоли UART приглашение входа показывает новое имя: `wukong login:`, а не `wukongpi login:`.
- [ ] Автоматического входа root нет.
- [ ] Вход под `tester` сразу даёт оболочку. Мастер создания пользователя не запускается, дополнительная перезагрузка не требуется.

Без UART проверьте это же по SSH в разделе 7: плата должна пустить вас без мастера.

## 6. Пользователь и sudo

```bash
hostname
id
sudo -v && echo SUDO_OK
sudo passwd -S root
```

- [ ] `hostname` выводит `wukong`.
- [ ] В группах есть `sudo`, `netdev`, `dialout`, `video`.
- [ ] `sudo` принимает ваш пароль.
- [ ] У root статус `L`: пароль `1234` заблокирован, раз пароль root не задан.

## 7. Сеть и SSH

Адрес платы посмотрите в роутере или в консоли (`ip -br addr`).

```bash
ssh tester@<адрес>
ssh -o PreferredAuthentications=password -o PubkeyAuthentication=no tester@<адрес>
ssh root@<адрес>
```

- [ ] Вход по ключу работает без запроса пароля.
- [ ] Вход по паролю работает.
- [ ] Вход `root` отклонён.
- [ ] `sudo sshd -T | grep -Ei '^(passwordauthentication|permitrootlogin)'` показывает `yes` и `no`.
- [ ] Ethernet: `nmcli device` показывает `connected` на проводном интерфейсе.
- [ ] Wi-Fi: `nmcli device` показывает `connected` на беспроводном интерфейсе. После отключения кабеля плата остаётся доступна по адресу Wi-Fi.
- [ ] Профиль Wi-Fi `/etc/NetworkManager/system-connections/wukong-wifi.nmconnection` имеет режим `600`, а `sudo grep psk= …` показывает 64 шестнадцатеричных символа, а не ваш пароль.

## 8. Имя `wukong.local`

В образе нет `avahi-daemon`. Плата ставит его сама через `apt` после выхода в сеть, поэтому имя зависит от `apt` и от интернета на плате: без них `wukong.local` не появится, а остальные настройки продолжат работать. Компьютеру тоже нужен mDNS: в Windows 10 и 11 он обычно уже есть.

**Известная проблема.** На образе 23.02.2 автоматическая установка сейчас не проходит. В `sources.list` образа есть `bullseye-backports`, которого больше нет на зеркалах, поэтому `apt-get update` завершается ошибкой, а пакеты avahi из `bullseye-security` для armhf отдают 404. В журнале при этом будет `FAIL avahi-daemon not installed`. Это видно уже в QEMU; пока скрипт не исправлен, считайте такую строку ожидаемой.

Обходной путь, проверенный в QEMU (установка занимает несколько минут):

```bash
grep -v -e bullseye-backports -e security /etc/apt/sources.list | sudo tee /run/wukong.list >/dev/null
sudo apt-get -o Dir::Etc::sourcelist=/run/wukong.list update
sudo apt-get -o Dir::Etc::sourcelist=/run/wukong.list install -y --no-install-recommends avahi-daemon
```

Проверка:

```bash
systemctl is-active avahi-daemon
ping wukong.local
ssh tester@wukong.local
```

- [ ] В журнале есть `OK avahi-daemon installed` или ожидаемая `FAIL avahi-daemon not installed`. Запишите, какая именно.
- [ ] После установки `avahi-daemon` активен, а `wukong.local` отвечает с компьютера. Вот это в QEMU проверить нельзя.

## 9. Оверлеи

```bash
grep -E '^(overlays|param_spidev)' /boot/armbianEnv.txt
ls /dev/i2c-* /dev/spidev*
```

- [ ] В `overlays=` есть `usbhost2`, `usbhost3`, `i2c0`, `spi-spidev`.
- [ ] Есть строка `param_spidev_spi_bus=0`.
- [ ] Устройства `/dev/i2c-*` и `/dev/spidev*` появились.
- [ ] USB-порты работают как раньше.

## 10. Свой скрипт

- [ ] Файл `/var/tmp/my-script-done` существует.
- [ ] `sudo grep 'user script' /var/log/wukong-firstboot.log` показывает `OK user script`, а выше в журнале есть вывод скрипта.

## 11. Журнал и уборка

```bash
sudo cat /var/log/wukong-firstboot.log
sudo ls -la /etc/systemd/system/armbian-firstrun.service.d/
ls /etc/systemd/system/wukong-post-network.service
sudo ls -la /root/.not_logged_in_yet
```

- [ ] В журнале по строке на шаг и нет `FAIL`, кроме разобранной выше строки про avahi. Есть `firstboot: finished`, `OK settings wiped`, `post-network: finished`.
- [ ] В журнале нет вашего пароля, хеша, ключа Wi-Fi и SSH-ключа.
- [ ] Каталог `armbian-firstrun.service.d`, а с ним `firstboot.env` и скрипты, удалены. Остальные команды тоже отвечают, что файла нет.

Журнал лежит в `/var/log`, а на Armbian это zram в памяти. После обрыва питания он может пропасть, хотя настройки применены: так и случилось в QEMU после жёсткой остановки. Поэтому смотрите журнал до выключения и не отключайте питание без `sudo poweroff`. Если журнала нет, это ещё не признак сбоя.

- [ ] После `sudo reboot` плата загружается заново, имя, пользователь, сеть и SSH на месте, настройка не повторяется.

## 12. Отказ Wi-Fi

Запишите карту заново с тем же профилем, но заведомо неверным паролем Wi-Fi или несуществующей сетью. Загрузите с подключённым Ethernet.

- [ ] Плата доступна по Ethernet, вход и `sudo` работают, остальные настройки применены.
- [ ] Плата не перезагружается сама. `journalctl --list-boots` показывает одну загрузку.
- [ ] `nmcli device` показывает, что Wi-Fi не подключён; UART работает.

## Что прислать при сбое

1. Какой шаг чек-листа не прошёл и что было вместо ожидаемого.
2. Вывод UART от включения до приглашения входа, если он есть.
3. С платы, если на неё можно зайти:

```bash
sudo cat /var/log/wukong-firstboot.log
sudo journalctl -b --no-pager -u armbian-firstrun -u wukong-post-network -u NetworkManager -u ssh
nmcli device; ip -br addr; ip route
sudo systemctl --failed --no-pager
```

4. Если зайти нельзя: вставьте карту в Linux и пришлите содержимое `/var/log` с раздела и каталог `/etc/systemd/system/armbian-firstrun.service.d/`, если он остался. **В `firstboot.env` лежат хеш и ключ Wi-Fi: его не присылайте, достаточно списка файлов.** Журнал в zram мог не сохраниться на карту, это тоже стоит указать.
5. Версию программы, размер и производителя карты, контрольную сумму образа.

Перед отправкой просмотрите вывод: пароли в нём быть не должны, а если они там есть, это само по себе ошибка, сообщите о ней и не пересылайте сам текст.
