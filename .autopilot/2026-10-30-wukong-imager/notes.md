## ГЛАВНОЕ (до деталей)

1. **PRESET_* в Armbian 23.02.2 НЕ существует.** `B/packages/bsp/common/usr/lib/armbian/armbian-firstlogin` (513 строк) интерактивный:
   `/root/.not_logged_in_yet` используется только как маркер (`-f`), содержимое не читается и не `source`-ится. `grep PRESET_` по `B/{packages,lib,config,extensions}` пуст.
   Всё, что делает `R/src-tauri/src/autoconfig.rs::render_preset` + `inject_into_image`, на этом образе молча ничего не даёт (запись пройдёт, маркер найдётся, эффект нулевой).
   Единственная штатная автоматизация 23.02: `/boot/armbian_first_run.txt` (только сеть, `FR_net_*`), см. раздел 9.
2. **vendored ext4 (`armbian-ext4fs`) на классическом ext4 образа не годится «как есть»**: снятие отказов -> паника деления на 0, а при обходе паники портит соседний дескриптор группы. Вердикт: маленький отдельный writer (раздел 8).
3. Для разового, узкого случая «перезаписать уже существующий файл» патч возможен, но шаблон «положить скрипт + drop-in + права 0600/0755 + symlink» библиотека не умеет (mode всегда 0777, symlink нет).
4. Образ Wukong: один раздел rootfs ext4 (MBR, `/boot` внутри rootfs, нет FAT), `mkfs.ext4 -q -m 2 -O ^64bit,^metadata_csum` (`B/lib/functions/image/partitioning.sh:32`). Значит писать можно только в ext4 rootfs.

## 8. ext4: crates/armbian-write-conf + vendor/armbian-ext4fs

Структура: `src/lib.rs` (`write_file_into_image`, `write_file_into_bare_ext4_image`, `rootfs_has_regular_file`, `PartDev: BlockDevice` с `unwrap()`/`panic!` на ошибках I/O), `src/detect.rs` (GPT/MBR через gptman/mbrman, выбор rootfs: GPT по имени root / GUID Linux FS / крупнейший; MBR тип 0x83 / крупнейший; `verify_ext4`, `verify_supported_ext4`), `src/validate.rs` (пост-проверка read-only через `ext4-view 0.9`: перечитывает файл, метаданные, обходит все каталоги). ext4-view нормально читает fs без metadata_csum.

`detect.rs::verify_supported_ext4` (L~170) сейчас отказывает: block size != 4096; НЕТ `metadata_csum` (RO_COMPAT 0x400) — это отсекает образ Wukong; `needs_recovery` (INCOMPAT 0x4); `64bit` и desc_size не 64 (или без 64bit и desc_size != 32; Wukong: desc_size 0 -> отказ); bigalloc; inline_data. inode_size НЕ проверяется.

Что делает vendored код, по пунктам запроса (все ссылки `crates/armbian-write-conf/vendor/armbian-ext4fs/src/`):
1. Stride дескрипторов: `ext4_defs/block_group.rs::load_new` и `sync_block_group_to_disk` используют СЫРОЙ `super_block.desc_size` (`BLOCK_SIZE / desc_size`) вместо `desc_size()` (который поднимает до 32). При s_desc_size = 0 это деление на 0 -> panic уже в `Ext4::open` (`ext4_impls/ext4.rs::get_system_zone` зовёт `load_new`). Т.е. «просто убрать отказ» = паника, в release = abort процесса.
2. Структура `Ext4BlockGroup` — 64 байта (с hi-полями). При 32-байтовых дескрипторах `load_new` читает 64 байта (вторая половина = СЛЕДУЮЩИЙ дескриптор), `sync_block_group_to_disk` пишет все 64 байта обратно (на конце блока GDT пишет за границу блока при bgid%128==127). hi-поля трактуются безусловно в `get_free_blocks_count` (`|= hi<<32` если hi != 0) и `set_free_blocks_count` (всегда пишет `free_blocks_count_hi`, смещение 0x2C = `free_blocks_count_lo` СОСЕДНЕЙ группы). Итог для classic: каждая аллокация блока обнуляет `free_blocks_count_lo` группы N+1 (и вычисляет мусорный счёт для группы N). Это реальная порча метаданных (ядро монтирует, но счётчики врут; e2fsck ругается).
   Защищены `desc_size > 32` только `set_free_inodes_count`, `set_itable_unused`, `get_*bitmap_block`. `set_used_dirs_count` пишет в `itable_unused_lo` (баг независимо от desc_size) -> при создании каталога счётчик dirs не растёт, itable_unused портится.
3. Контрольные суммы пишутся безусловно: `sync_to_disk_with_csum` (bg) считает crc32c и кладёт в `bg.checksum` (0x1E), суперблок `sync_to_disk_with_csum` пишет `s_checksum` (0x3FC), `write_back_inode` кладёт crc32c в `l_i_checksum_lo` (0x7C) и `i_checksum_hi` (0x82), `dir_set_csum` пишет «tail» crc32c в последние 4 байта КАЖДОГО изменяемого блока каталога. Условие `metadata_csum` проверяют только битмапы (`features_read_only & 0x400`) и extent-блоки. На fs без `metadata_csum` и без `uninit_bg(0x10)` (у Wukong ro_compat 0x6b) ядро эти поля игнорирует, поэтому безвредно, КРОМЕ последних 4 байт блока каталога: если новая запись встанет точно в конец блока, имя перезапишется crc. На fs с `gdt_csum` (crc16) запись crc32c в bg.checksum сломала бы проверку.
4. Битмапы: `utils/bitmap.rs` + `balloc.rs::balloc_alloc_block` корректны для flex_bg (положение берётся из дескриптора), но выбор без цели стартует с группы 1 (`1 % group_count`); `ialloc.rs` ок для inode, есть баг `ialloc_free_inode` (`decrease_free_inodes_count` вместо increase, не используется нами). `inode.rs::allocate_new_block` ищет бит как относительный индекс без преобразования в абсолютный блок (корректно только в группе 0), используется `append_inode_pblk`/`balloc_alloc_block_batch`? Непосредственно write_at идёт через `append_inode_pblk_batch` -> `balloc_alloc_block_batch`; путь с багом `allocate_new_block` вне основного потока, но не проверен тестом.
5. htree: `file.rs::create`/`create_with_attr` проверяют `EXT4_INODE_FLAG_INDEX` (0x1000) и отказывают `ENOTSUP` «Cannot add entries to a hash-indexed directory». То есть htree уважается как «отказ», не как корректная вставка: безопасно, но в каталог с INDEX_FL (в Debian это `/etc`, `/usr/lib`, `/lib/systemd/system`, `/usr/share/*`…) новый файл добавить нельзя. Перезапись СУЩЕСТВУЮЩЕГО файла каталог не меняет. `dir.rs::try_insert_to_existing_block` предполагает 12-байтовый tail (`BLOCK_SIZE - size_of::<Ext4DirEntryTail>()`); на fs без csum заканчивается рабочей записью, но для новых блоков создаёт фейковый tail (inode=0, безвредно).
6. Inode size: `Ext4Inode` = 160 байт (0xA0), `sync_inode_to_disk` пишет 160 байт независимо от `s_inode_size`: при inode_size 128 затирается начало следующего inode. Checksum считается по `inode_size` байтам, где за пределами 0x9C нули (неверно для существующих inode при metadata_csum). Для 256-байтовых inode (дефолт mke2fs для fs > 512 МБ) нормально.
7. mkdir и режимы: `simple_interface::ext4_dir_mk` создаёт каталоги; `generic_open` при отсутствии промежуточных компонентов создаёт их как каталоги (mkdir -p). `file.rs::create_inode`: `inode.set_mode(inode_mode | 0o777)` — ВСЕГДА 0777 для любого нового файла/каталога (нельзя 0600/0644/0755); uid/gid только через `create_with_attr` (simple_interface его не вызывает) => владелец root:root; времён нет (mtime=0). Существующий файл при `"w+"` сохраняет inode (режим/владелец), блоки усекаются и пишутся заново.
8. Symlink: нет API создания (`InodeFileType::S_IFLNK` определён, но нигде не создаётся); `ext4_file_open` на не-regular -> `EISDIR`. `dir_find_entry` содержит `assert!(parent.inode.is_dir())`: путь через симлинк/файл = panic.
9. Паники: `PartDev::read_offset/write_offset` `unwrap()`/`panic!` на I/O; `Block::write_offset` `panic!`; `assert!` в `dir_find_entry`/`dir_has_entry`/`dir_remove_entry`; деление на 0 (п.1); арифметика `usize` без проверок (`rec_len - used`). 75 `unwrap/expect/assert` вне тестов и fuse. В release (`panic=abort`) любая паника убивает приложение; `prepare_flash_copy` ловит JoinError только при unwinding (в debug).

Что нужно было бы в патче, чтобы работать с classic-образом: (a) `desc_size()` в load/sync; (b) читать/писать ровно `desc_size` байт и маскировать hi-поля при desc_size<=32 (getters/setters); (c) условные чек-суммы по фичам (`0x10|0x400`, dir tail только при 0x400); (d) fix `set_used_dirs_count`; (e) проверка `s_inode_size >= 160`; (f) режим/владелец/symlink API; (g) заменить `unwrap/panic` на `Result`; (h) тесты на образе без csum (текущий `mkext4` в тестах строит только csum-вариант) + проверка `e2fsck -fn` на выходе.

**Вердикт: маленький отдельный writer.** Причины: (1) просто снять отказы нельзя (паника, затем порча соседних дескрипторов); (2) патч затрагивает 5+ файлов в чужом, плохо тестированном коде с `unwrap`-ами, где любая ошибка = abort во время флеша; (3) нужные нам операции шире, чем умеет библиотека: файлы с режимами 0600/0644/0755 (NetworkManager `system-connections/*.nmconnection` с 0777 НЕ будет загружен: «insecure permissions»; `authorized_keys`, скрипты +x), владелец root (OK), каталоги, symlink (`multi-user.target.wants/…`), вставка в htree-каталоги; (4) классика проще: 4K блоки, 32-байтовые дескрипторы, нет csum, extents — достаточно ~500-800 строк: чтение через уже имеющийся `ext4-view` (поиск inode по пути) + свой аллокатор (битмап из дескриптора с flex_bg, учёт `free_*` в group desc и суперблоке, один extent в inode.i_block, до 4 extent'ов inline) + вставка dirent в линейный каталог; для htree-каталогов — снять `EXT4_INDEX_FL` у inode каталога и добавлять линейно (ядро и e2fsck это принимают), либо ограничить список целевых путей малыми каталогами (`/root`, `/boot`, `/etc/systemd/system`, `/usr/local/sbin`, `/etc/NetworkManager/system-connections`, `/etc/ssh/sshd_config.d`). **armbian-firstrun** (`armbian-firstrun`, юнит `/lib/systemd/system/armbian-firstrun.service`): `Type=simple`, `RemainAfterExit=yes`, `Before=getty.target system-getty.slice`, `WantedBy=multi-user.target`, `TimeoutStartSec=2min`, комментарий «runs in parallel with other services»; НЕТ Before/After для `ssh.service`/`NetworkManager.service`. Делает: правит htoprc и копирует `/etc/skel/.config` в `/root`; iozone-бенчмарк в лог; `setupcon --save`; дописывает `IMAGE_UUID` в `/etc/armbian-image-release`; **SSH host keys: `rm -f /etc/ssh/ssh_host*`, `dpkg-reconfigure openssh-server`, `service sshd restart`** (ключи генерируются здесь, на первой загрузке, не на этапе сборки); рандомизирует `ethaddr=`/`eth1addr=` в `/boot/armbianEnv.txt` (только если такие строки есть, sed-замена); для sun7i|sun8i блок bluetooth/MAC — на `LINUXFAMILY=sunxi` не срабатывает; в конце **`systemctl disable armbian-firstrun`** (одноразовый, юнит-файл остаётся).
- Drop-in `/etc/systemd/system/armbian-firstrun.service.d/*.conf` с `[Service] ExecStartPre=` будет выполнен ДО ExecStart; для `Type=simple` юнит считается started только после завершения ExecStartPre, поэтому благодаря `Before=getty.target system-getty.slice` ExecStartPre отработает до getty (и до автологина на консоли). Затем firstrun сам сделает `rm ssh_host*` + regenerate + restart sshd. ExecStartPre не должен падать: префикс `-` или `|| true`. После первого запуска drop-in инертен (юнит disabled).

## Ловушки (Traps)

1. PRESET_* (раздел 3) на 23.02.2 не работает: `render_preset` + запись в `/root/.not_logged_in_yet` бесполезны; нужна собственная схема (скрипт первой загрузки, `/boot/armbian_first_run.txt` для сети).
2. Если удалить `.not_logged_in_yet`, автологин root на консоли/serial остаётся навсегда (override.conf снимает только firstlogin); свой скрипт обязан их удалить и `systemctl daemon-reload`.
3. `armbian-ext4fs`: любые файлы получают mode 0777 (NetworkManager отвергает `.nmconnection` с широкими правами), нет symlink/chmod/chown, в htree-каталоги (`/etc`, `/usr/lib`, `/lib/systemd/system`) вставка отказывает; снять отказы без правок = division-by-zero panic -> abort (`panic=abort`).
4. Пароли профилей и Wi-Fi ключ лежат в `settings.json` открытым текстом; рабочая копия образа с паролями на диске (Windows ACL профиля, не 0600); `.not_logged_in_yet` в образе тоже открытый текст.
5. Диск: нужна полная вторая копия распакованного образа (`custom-decompress` + `autoconfig-temp`); при инъекции стадия «copying» долгая.
6. Любой USB-накопитель считается не системным и выбирается как цель; на Windows приложение требует админа (UAC) при каждом запуске, `tauri dev` тоже.
7. `createUpdaterArtifacts:true` + pubkey Армбиан: сборка без ключа падает; плагин updater ходит на github.com/armbian. `check_connectivity` ходит на api.armbian.com: при его недоступности включается offline-макет, и сброс выбора в App.tsx:247-256.
8. `BOARD_IMAGES_BASE`/`VENDOR_IMAGES_BASE` не следуют `ARMBIAN_API_BASE`; QDL-код тянет git-зависимость (qdlrs) и nusb.
9. `.iso` в диалоге есть, но декомпрессии/автоконфига для него нет; `.img.gz/.zst` автоконфиг получают только если плата сопоставилась по имени.
10. Скрипты сборки/ CI/ README/ locales (20 файлов) упоминают Armbian; workflows `delete-releases`/`data-sync-locales` по расписанию и `maintenance-pr-check` на push main будут срабатывать в форке; `release` на теги `v*` требует секретов подписи.
11. На устройстве нет `avahi-daemon` (нет `wukongpi.local`), время через `chrony` без RTC (fake-hwclock), пароль root по умолчанию `1234` и `PermitRootLogin yes`: без смены пароля первая загрузка небезопасна.
12. `armbian-firstrun` помечен «parallel»: порядок относительно ssh/NetworkManager не гарантирован, SSH host keys пересоздаются им при первой загрузке (нельзя заранее положить свои ключи без изменения скрипта).
