# 02 — Запись файлов в классический ext4 образа Wukong

**Требования:** R14, R25i
**Зависит от:** —
**Зона:** `crates/classic-ext4/`
**Волна:** 1
**Ревью:** нет
**Модель:** сильная

## Что должно заработать

Библиотека создаёт каталог и файлы с заданными режимами в ext4 образа Wukong на любом компьютере, без монтирования и прав администратора. После этого `e2fsck -fn` не находит ошибок, а чужие файлы образа остаются целыми.

## Разделы спецификации

Истории 40, 41. Решения: «Свой писатель». `interfaces.md` §1. `notes.md` §8. Параметры образа: 4K, incompat 0x242, ro_compat 0x6b, compat 0x3c, `s_desc_size` 0, MBR, раздел с 4 МиБ. Настоящий образ: `D:\Projects\Wukong\wukongpi-bullseye\images\Armbian_23.02.2_Wukongpi_bullseye_current_5.15.93.img` — **только чтение, работать с копией** (путь через `WUKONG_TEST_IMAGE`; тест пропускается без него). Копии класть в scratch вне репозитория и удалять.

## Критерии приёмки

- [ ] API `ClassicExt4` как в `interfaces.md`, crate под MIT, отдельный от workspace, как `armbian-write-conf`
- [ ] Новый каталог и файлы до 1 МиБ получают заданный режим, root:root, корректные времена; файл читается обратно через `ext4-view`
- [ ] Счётчики свободных блоков и inode в дескрипторах и суперблоке, `used_dirs`, `links_count` родителя верны
- [ ] Файл нескольких блоков и каталог с большим числом записей корректны; блок каталога расширяется при заполнении
- [ ] Отказы `Unsupported` для всех случаев из `interfaces.md`, включая родителя с `EXT4_INDEX_FL`; нет паник на обрезанном или мусорном образе (тест)
- [ ] До `commit` файл на диске не меняется (тест по хешу)
- [ ] Фикстура собрана `mkfs.ext4 -O ^64bit,^metadata_csum` в Docker; `crates/classic-ext4/scripts/fsck-check.sh` гоняет `e2fsck -fn` в Docker на результате
- [ ] На копии настоящего образа: вставка в `/etc/systemd/system/armbian-firstrun.service.d/` проходит, `e2fsck -fn` чист, `debugfs` показывает режимы
