# Спецификация: Wukong Imager

## Задача

Плата Wukong Pi Zero настраивается только руками: образ из `wukong-build` записывается на карту, затем нужна консоль UART, чтобы задать пользователя и подключить сеть. Хочется как в Raspberry Pi Imager: указать настройки на компьютере, прошить, вставить карту и сразу зайти на плату по SSH.

Armbian Imager (проанализирован, вывод ниже) подходит как основа, но с образами Wukong его настройки не работают.

## Решение

Настольная программа Wukong Imager для Windows и Linux. Она открывается сразу с платой Wukong Pi Zero. Пользователь выбирает образ с диска или из каталога, выбирает карту, заполняет настройки или берёт сохранённый профиль и запускает прошивку. Программа проверяет запись. При первом включении плата применяет настройки сама, до появления приглашения входа, и больше о них не помнит.

### Анализ Armbian Imager (R20)

| Что | Вывод |
|---|---|
| Запись, проверка, защита дисков, GUI, русский язык | берём как есть |
| `PRESET_*` на Armbian 23.02 | не работает: `armbian-firstlogin` не читает файл как настройки |
| `armbian-ext4fs` на классическом ext4 образа | не подходит: паника при `s_desc_size=0`, порча соседнего дескриптора, режим 0777 |
| Каталог, обновления, логи | привязаны к Armbian, отключаются |
| Вердикт | форк, с собственным писателем ext4 и своим механизмом первой загрузки |

## Решения по реализации

- **Форк `Kostec/imager`, ветка `wukong`.** Upstream подключён как `upstream`. Правки точечные, чтобы брать обновления.
- **Свой писатель `classic-ext4`, не патч `armbian-ext4fs`.** Патч затрагивает 5+ файлов чужого кода, где любая ошибка — abort посреди записи. Нам нужно мало: каталог и файлы с нужными режимами в одной маленькой директории. Чтение — `ext4-view`.
- **Точка входа — drop-in на `armbian-firstrun.service`.** Служба уже включена и стоит `Before=getty.target`, поэтому не нужен симлинк в `*.wants` и вставка в большие каталоги с htree. Всё остальное скрипт делает на устройстве обычными средствами.
- **Два этапа на устройстве.** `firstboot.sh` — до сети, до getty, NetworkManager и ssh: hostname, пользователи, SSH, сетевые профили, регион, оверлеи, снятие автологина. Затем он создаёт через `systemctl enable` одноразовую службу с `post-network.sh`: ждёт маршрут до 120 с и синхронизацию `chrony`, ставит `avahi-daemon`, запускает свой скрипт, затирает всё за собой.
- **Запрет SSH** — `systemctl mask ssh`: `armbian-firstrun` делает `service sshd restart`, простой `disable` его бы не остановил.
- **Настройки sshd** — `/etc/ssh/sshd_config.d/10-wukong.conf`, если в `sshd_config` есть `Include`; иначе правка строк. После записи `sshd -t`, при ошибке откат.
- **Ключ GitHub берётся на компьютере** — расширяется существующий `ssh_keys.rs`. Upstream отдавал URL плате.
- **Хеши** — `sha-crypt` (`$6$`), `pbkdf2` + `sha1` (4096 раундов). Bullseye и Jammy понимают `$6$`. WPA3 не поддерживается, как решено.
- **Встроенный каталог** — константа в Rust, без образов: образ приходит из файла или внешнего каталога. Формат `catalog.json` свой и простой; для Docker достаточно nginx.
- **Проверка соединения** — без `api.armbian.com`. При встроенном каталоге программа всегда «онлайн»; при URL-каталоге проверяется сам URL.
- **Внешние запросы убираем** — MOTD, Google Fonts (системный шрифт), ссылки на форум и донаты Armbian. Адрес проекта — `Kostec/imager`. Оригинал и лицензия в «О программе» и README.
- **QDL и macOS** — не трогаем, в интерфейсе для Wukong не появляются.
- **Идентификатор** — `io.github.kostec.wukongimager`, бинарник и пакет `wukong-imager`, кэш `wukong-imager`.
- **e2e** — dev-пример `examples/provision.rs` (не CLI для пользователей), Docker: `e2fsck -fn`, QEMU `-M orangepi-pc` с ядром и dtb из образа.

## Вне рамок

| Требование | Почему не сейчас |
|---|---|
| R03, R05 — zip | снято пользователем |
| R17 — CLI | снято пользователем |
| Сборка ISO в `wukong-build` | не нужна: плата грузится с SD, условие «если необходимо» не наступило |
| Изменения `wukong-build` | вариант «а» |
| Образы с `metadata_csum` и иной ФС для настроек | образы Wukong классические; такой образ пишется без настроек с объяснением |
| WPA3, Enterprise | решено: только WPA2-PSK и открытые сети |
| Подпись установщика, автообновление | решено пользователем |
| Проверка Wi-Fi и записи на реальную карту автоматически | нет платы; чек-лист G06 |
| macOS, QDL | код остаётся, не проверяется |
| Сервер каталога | только пример с nginx |

## Открытые места

- **`имя.local`** — в образе нет `avahi-daemon`, поэтому он ставится на плату через `apt`, это несколько минут и нужен интернет. Надёжное решение — одна строка в `wukong-build`; она не входит в вариант «а» и останется рекомендацией в отчёте.
- **Значок программы** — нейтральная заглушка, своего логотипа Wukong у нас нет.
- **Фото платы** — без него: нейтральный значок вместо картинки.
- **Загрузка образа в QEMU** — не подтверждена, H2+ эмулируется как H3. Если не загрузится, остаётся прогон скриптов в Docker и чек-лист.
