- Пароли: «Все четыре меры» — на карте и в профиле только хеш и производный ключ Wi-Fi, файл затирается после первой загрузки, Wi-Fi только WPA2 (R26i)
- Применяется только заполненное; пустые настройки — образ без изменений (G08)
- Код других плат и macOS не трогать и не проверять, установщик без подписи, автообновление и отправка логов выключены (G10)
- Проверку на плате пользователь делает сам по `docs/hardware-checklist.md` (G06)
- Открытые сети Wi-Fi без пароля остаются: «WPA2» значит WPA2-PSK, а не WPA3 — пользователь выбрал «Оставить открытые» (R26i)

## Известные баги

- Импорт ключей с GitHub: первая попытка может упасть по таймауту при живой сети, повтор проходит
- Страна Wi-Fi скрыта в мастере, в английском интерфейсе молча ставится US — сети на каналах 12–13 могут быть не видны
- Строка «# ssh-rsa AAAA» считается ключом — запрет «SSH без пароля и без ключей» обходится
- Зарезервированные логины проверяет только форма; после ручной правки settings.json `nobody` получит sudo
- Если служба второго этапа не создалась (диск полон или только чтение), файл с хешами и ключом Wi-Fi остаётся на карте
- Windows: после падения программы копия образа с хешами живёт до запуска спустя 12 часов
- Каталог: файл и sha256 заменены при том же имени — запишется старый образ из кэша без сверки
- Свой скрипт выполняется не больше одного раза: обрыв питания во время него не повторяет его
- Остаток после затирания не дочищается, если обрыв попал в короткий миг между удалением и уборкой (секретов там уже нет)
- Проба образа не проверяет, примет ли /etc/systemd/system новую запись — отказ придёт только при записи
- e2e: проверка «без лишней перезагрузки» не может покраснеть (журнал volatile); падение device-test на середине не считается ошибкой
- Шелл-сценарии скриптов устройства не в репозитории
- Причина сбоя Wi-Fi от настоящего адаптера проверена только на заглушках
- Чек-лист §11 — возможно неверный путь к журналу на карте в чужом Linux; путь settings.json выведен, не проверен
- На Windows `cargo test` и `npm run tauri:dev` требуют терминала администратора (os error 740)
- Мелочи: двойник каталога `src/config/wukong.ts` без теста сверки; `render_qdl_preset` расходится с interfaces; после сборки git показывает `src-tauri/Cargo.toml` изменённым из-за окончаний строк
